
# 二叉搜索树
- 任何节点的左子节点都小于当前节点的键值；右子节点都大于当前节点的键值


# 平衡二叉树（AVL）
- 如果所有节点都是其父节点的左节点或所有都是右节点 ，那就变成链表
	- 高度太高，查找效率不稳定

- 在二叉搜索树的基础上，要求***每个节点的左右子树的高度差不超过1***


# B树（Balance Tree）
- 二叉搜索树、AVL树、红黑树都是在***内存***中进行
- ==单个节点可以存储多个键值和数据的平衡树==
- B树访问节点是在硬盘上进行的，节点内对数据的操作时在内存进行的
	- 每个节点称为页，页就是磁盘块，在 MySQL 中数据读取的基本单位都是页
	- 子节点的个数一般称为阶，图中的 B 树为 5 阶 B 树

![[Pasted image 20251022102141.png]]

- 三个特点
	- 平衡：所有叶节点都在同一层
	- 有序：任一元素的左子树都小于它，右子树都大于它
	- 多路：对于 m 阶 B 树的节点
		- 最多：m个分支，m-1个元素
		- 最少：
			- 根节点：2个分支，1个元素
			- 其他节点：[m/2] 个分支，[m/2] - 1 个元素

- target与节点内的元素一次比较，找到第一个比它大的，然后走其左子树，走到最后都没有，就走最后的右子树

## B树插入
1. 先找到插入的位置进行插入   ---插入的位置一定在叶节点
2. 如果没有上溢出，无需调整（不超过最多节点个数）
3. 否则中间元素（[m/2]）上移，两边分裂（直到没有上溢出为止）

## B树删除
- 删除非叶节点元素最终都转换成删除叶节点元素
	- 先通过前驱或后继的替换，转换成删除叶节点
- 删除叶节点元素
	- 没有下溢出无需调整
	- 有下溢出
		- 兄弟够借：借
			- 父下来，兄上去
		- 兄弟不够借：合并 （可能导致父节点下溢出）
			- 父下移到左，然后右合并过来


# B+树
- ***叶子节点层包含所有元素***，从小到大连接起来（链表）

![[Pasted image 20251022114441.png]]

- B+树常被用做数据库中的索引结构
	- B+树本身也是作为一个索引文件存储在硬盘中
	- 节点内的元素被称作关键字
		- 每个元素都包含指向记录存储地址的指针
		- 通过关键字包含的指针，可以索引到数据库中的某一条记录
		- 可以给同一个数据表构建多个不同关键字的索引
	- 非叶子节点帮助快速定位到叶节点上的某一个关键字
		- 相当于给叶节点层建立了索引
		- 非叶子节点也只是用来索引下一级的

- B+树的元素个数与分支相同，一个元素只对应一个子树
- 非叶子节点，每个元素都是其子节点的最大值

## B+树的查找
- ***最终一定会落在叶子节点上***，比如找18，非叶子节点中的18，只是索引，只有找到叶子层中的18，才能找到记录
