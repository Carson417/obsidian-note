# 技术常识

## 硬件基础

### 显存

显存：**显示内存（Video RAM，简称VRAM）**，它是**显卡上**专门用于临时存储图像、视频、3D模型等图形数据的专属高速内存。

当电脑要显示画面，CPU会把相关的图形数据先交给显卡的GPU（图形处理器）计算，计算过程中需要的中间数据和最终的画面帧，都会暂时存放在显存里，最后再由显存输出到显示器上。

电脑的普通内存（RAM）是给整机系统（CPU、软件等）用的，而显存是显卡独占的高速存储。

## 开发工具

### Node.js

Node.js = JavaScript的运行环境，让JavaScript脱离浏览器、在电脑/服务器上运行的环境。以前JavaScript主要运行在浏览器里，但是有了 **Node.js** 以后，JavaScript就可以像Java、Python一样，在电脑命令行、服务器后台运行。

### npm

**npm = Node Package Manager**，可以理解为 **Node.js的"软件安装器/依赖管理工具"**。

| 名称 | 作用 |
|---|---|
| **Node.js** | 运行JavaScript程序的环境 |
| **npm** | Node.js自带的包管理工具，用来安装各种工具包 |
| **npm包** | 别人写好的JavaScript工具、库、命令行程序 |

## AI 模型基础

### Transformer

Transformer是一种AI模型结构。作用是：让模型理解一段文字里，哪些词和哪些词之间关系更重要。

### Attention

Transformer里面最核心的是 **Attention**，中文一般叫**注意力机制**。模型在计算：当前这个词，需要重点参考哪些其他词？

### LLM

Large Language Model，专门处理语言的大模型。如GPT，Claude，Gemini。

### Parameters

参数。会看到如 7B、14B，这里的 B 指的是十亿（Billion）。

### Token

Token是大模型处理文字的基本单位。它不是严格等于一个字，也不是严格等于一个词。

上下文长度 32K、上下文长度 128K，指的就是模型一次最多能处理多少token。详见 [[#Context Window]]。

### Context Window

上下文窗口，模型一次能"看见"的内容长度。与 [[#Token]] 密切相关。

## AI 应用技术

### Agent

能自己规划步骤、调用工具、完成任务的AI程序。

| 概念 | 是什么 | 类比 |
|---|---|---|
| **Transformer** | 模型结构 | 大脑的底层结构 |
| **大语言模型** | 用Transformer训练出来的模型 | 一个会理解和生成文本的大脑 |
| **Agent** | 基于模型构建的任务执行系统 | 会用工具干活的助手 |

```
Transformer
   ↓
大语言模型，比如GPT、Claude、Gemini
   ↓
Agent
   ↓
调用工具、读文件、写代码、执行命令、完成任务
```

### RAG

RAG = Retrieval-Augmented Generation，检索增强生成。先查资料，再让大模型根据查到的资料回答。

```
用户提问
   ↓
系统去知识库里检索相关内容
   ↓
把检索到的内容交给大模型
   ↓
大模型基于这些资料生成答案
```

#### RAG常见组件

1. **文档** — RAG的知识来源
2. **切片（Chunk）** — 文档通常很长，不能整篇都塞给模型，所以要切成小块
3. **向量（Embedding）** — 系统把每个chunk转换成一串数字，用来判断"用户问题"和"哪段文档内容最相关"
4. **向量数据库（Vector Database）** — 用来存储这些向量
5. **大模型** — 负责最后一步生成答案

```
             文档 / 代码 / 数据库
                    ↓
              文档切片 chunk
                    ↓
              生成向量 embedding
                    ↓
              存入向量数据库


用户问题
   ↓
问题转向量
   ↓
去向量库检索相关chunk
   ↓
把chunk + 问题交给大模型
   ↓
生成答案
```

### MCP

Model Context Protocol，可以简单理解为：让大模型连接外部工具、数据源、系统的一种协议。

## 模型使用技巧

### Prompt

提示词，给模型输入的要求。

### System Prompt

系统提示词，它比普通用户输入优先级更高，用来规定模型的角色、风格、规则。

```
你是一个Java代码助手
回答要简洁
不要编造
优先给可执行命令
```

### Prompt Engineering

提示词工程。意思是：通过更好的提问方式，让模型给出更好的结果。

普通问法：
```
帮我看代码。
```

更好的问法：
```
请帮我检查下面这段Java代码是否会出现空指针异常，并说明原因，最后给出修改后的代码。
```

## 模型训练

### Training

训练，用大量数据让模型学习语言、代码、知识、规律。

### Pre-training

预训练，这是大模型最早的大规模训练阶段。目标是让模型学会通用语言能力、知识和推理模式。

### Fine-tuning

微调，在已有大模型基础上，用特定领域数据继续训练，让它更适合某个场景。

## 模型行为

### Hallucination

幻觉，模型一本正经地说错话。

### Temperature

温度，控制模型回答的随机性。

| Temperature | 效果 |
|---|---|
| 低 | 更稳定、更保守、更适合代码/事实问题 |
| 高 | 更发散、更有创意、更适合写作/头脑风暴 |

## 环境变量

## 异步注解 @Async
### 使用方式
1. 在启动类上加 @EnableAsync
2. 需要执行异步方法的方法上加 @Async

### 问题场景
在一个类中有A和B两种方法，A调用B，B需要耗时很久，需要将B异步执行
```java
class test{
	A(){
		B();
	}
	
	@Async
	B(){}
}

// 但是这种写法，A的用时还是很长
```

#### 可能使 @Async 失效的原因
1. 事务管理：如果 AB 在同一事务上下文中，那事务提交可能会阻塞直至 B 完成
2. 没有通过代理对象调用，而是A直接调用B，那注解不会生效

#### 为什么一定要通过代理对象调用才行？
因为 spring的AOP（面向切面编程）依赖于代理对象来实现方法拦截和增强
- AOP代理
	- AOP使用动态代理来创建对象的代理，对于接口实现类， Spring会使用JDK动态代理，对于没有实现接口的类，Spring会使用CGLB代理
	- 当一个类的方法被调用时，如果该方法被 @Async 注解标记，Spring会通过代理对象拦截这个调用，并在一个新的线程中执行实际的方法逻辑
- Spring容器管理
	- Spring容器负责管理Bean的生命周期和依赖注入。只有由Spring容器管理的Bean才能享受Spring提供的各种功能，包括AOP、事务管理
	- 当你在一个类中直接调用另一个类的方法，这是普通的java方法调用，不是通过spring容器管理的代理对象进行的调用
